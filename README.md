# repro-st-aster

This repository contains the code and notebooks used for the ASTER analyses. The data
are kept outside GitHub because of their size and are provided as a separate archive.

## Repository layout

```text
src/repro_st_aster/     analysis and model code
notebooks/              notebooks for the five workflows
scripts/                optional command-line entry points
raw_data/               raw tissue data
preprocess_data/        prepared inputs and intermediate outputs
results/                figures and summary files generated by a run
```

## Getting the data

Download `repro-st-aster-data-upload.tar.zst` from the project Google Drive link:

`<ASTER_DATA_ARCHIVE_URL>`

The archive is about 31 GB. After downloading it, place it anywhere convenient and run
the following commands **from the root of this repository**:

```bash
tar --zstd -xf /path/to/repro-st-aster-data-upload.tar.zst
for package_dir in upload/*; do
    cp -a "$package_dir"/. .
done
```

The archive first creates an `upload/` directory. Its numbered folders contain paths
that belong in the repository, so the second command copies their contents into the
right places. The numbered folders themselves should not be left inside `raw_data/` or
`preprocess_data/`.

The data are grouped as follows:

- Breast Xenium: `01_bc_raw` goes to `raw_data/bc_xenium/`; `02_bc_precomputed` goes to
  `preprocess_data/bc_xenium/`. The optional `02b_bc_uni_only` folder contains only the
  breast UNI feature grid.
- CRC Visium HD: `03_crc_raw_st` and `04_crc_he` go to `raw_data/crc_visiumhd/`;
  `05_crc_uni` goes to `preprocess_data/crc_visiumhd/uni/`.
- Gastric Xenium: `06_gastric_raw_st` and `07_gastric_he` go to
  `raw_data/gastric_xenium/`; `08_gastric_uni` goes to
  `preprocess_data/gastric_xenium/uni/`.
- DLPFC: `09_dlpfc` goes to `preprocess_data/dlpfc/`.
- Simulation: `10_simulation` goes to `preprocess_data/simulation/`.

Once the files are in place, this quick check will report anything missing:

```bash
python scripts/check_data.py
```

## Running the analyses

The notebooks are the main way to use the repository. Install the packages listed in
`requirements.txt`, open a notebook from the repository root, and run its cells in
order. Since the source code is kept under `src/`, set the source path for the notebook
kernel if it is not already configured:

```bash
export PYTHONPATH="$PWD/src"
```

The notebooks cover the following workflows:

- `BC_Xenium_Breast_Cancer_Demo.ipynb` displays the supplied breast precomputed results
  and figures. Full breast retraining is available through the command-line stages.
- `CRC_VisiumHD_Colorectal_Cancer_Demo.ipynb` runs the CRC workflow from raw data to
  the K=15 spatial domains.
- `Gastric_Xenium_Gastric_Cancer_Demo.ipynb` runs the gastric workflow from raw data to
  the K=17 spatial domains.
- `Simulation_ASTER.ipynb` runs the simulation benchmark.
- `DLPFC_ASTER.ipynb` runs ASTER reconstruction on the 12 DLPFC slices.

For a quick test, the CRC and gastric notebooks provide a `SUBSET_N` setting. Leave it
as `None` for a full run.

The `scripts/` directory is optional. These shell commands call the same Python modules
as the notebooks, one stage at a time. They are useful when a run is long or needs to
be repeated later: each stage can be run independently, logged, or submitted to a
cluster. They are not required for the CRC, gastric, simulation, or DLPFC notebooks.

For example, the CRC command-line workflow is:

```bash
bash scripts/prepare_crc_visiumhd_bcam_input.sh
bash scripts/reproduce_crc_visiumhd_inr.sh
bash scripts/reproduce_crc_visiumhd_fusion.sh
bash scripts/reproduce_crc_visiumhd_cluster.sh
```
